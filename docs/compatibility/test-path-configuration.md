# Local test path configuration

Copy `.test-paths.example.json` to `.test-paths.local.json` at the repository
root. The actual local file is ignored by Git; never add it with `git add -f`.
All three Release export presets also exclude the local file from packages.
Only the example schema is shared. `RGSS_TEST_PATHS_FILE` can select another
JSON file for a guest or CI workspace. Relative values resolve against that
configuration file's directory.

| Key | Local input |
| --- | --- |
| `game_project` | Installed RMProject directory containing Data and Game.exe |
| `rtp` | Installed licensed RTP directory |
| `godot` | Godot .NET executable |
| `ffmpeg` | Original-signal encoder/capture executable; WMA tests prefer the bundled decoder |
| `docker` | Container CLI executable |
| `git_bash` | Bash executable used to parse POSIX scripts on Windows |
| `vs_devcmd` | Visual C++ environment batch file |
| `mruby_source` | Native build checkout with matching headers |
| `mac_workspace` | Remote Mac verification workspace |
| `mac_host` | Existing SSH alias for the Mac test machine |
| `audio_device` | Original-runtime loopback capture device name |
| `audio_device_secondary` | Second output route used only by the route comparison probe |
| `linux_build_image` | Locally prepared Linux build/test container image |

The repository root and repository-owned fixtures are never configuration
values. They derive from the active checkout. Test output directories derive
from `.omo/evidence` and are created by each owner; tests must not depend on a
previous test creating them. Deliberately nonexistent inputs for error tests
also live in the isolated test output tree.

Loaders share this file across GDScript, Ruby, PowerShell, Bash and Python.
Tests use `tools/test_paths.gd`; original Ruby fixture preparation embeds the
resolved globals and `tests/fixtures/test_paths.rb` into its isolated project.
PowerShell tools dot-source `tools/test_paths.ps1`; shell tools source
`tools/test_paths.sh`. Python uses `tools/test_paths.py`.

Only required external keys must be configured for a given test. Missing keys
fail with the key and configuration filename instead of reading a workstation
fallback. Data-independent CI contracts still run without a local config.
Full database/game/RTP owners require their corresponding inputs; skipping
them does not mean the complete suite passed.

`tools/check_test_paths.py` rejects literal drive/user workspace paths in test
and verification source files. It does not scan the ignored local JSON or
change exact original goldens. Container `/repo` and `/output` mounts, system
device APIs and registry keys are execution contracts, not workstation file
inputs.

Validation entrypoints are `tools/test_path_contract.ps1`,
`tools/test_path_contract.gd` and `tools/test_path_missing.ps1`. The missing-key
contract requires the temporary empty config generated by the local validation
run. These checks do not commit or publish configuration values.

For containers, bind configured host inputs to the declared `/game-data`,
`/game` or `/rtp` mount. Generate a container-local JSON selecting those paths
and point `RGSS_TEST_PATHS_FILE` at it. A host drive path in a container JSON
does not identify a mounted input. Mac tools likewise need a Mac-local JSON
beside their tools, rather than inheriting Windows paths.
